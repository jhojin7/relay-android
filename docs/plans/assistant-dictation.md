# 어시스턴트 버튼으로 현재 입력창에 받아쓰기

작성일: 2026-11-06. 기준: `origin/main`의 `3864f18`.
상태: 2026-11-22 구현 및 에뮬레이터 검증 진행. 아래는 원래 계획이며 구현 차이는 문서 끝에 기록한다.
근거: [Android·삼성 조사](../research/assistant-dictation.md).

## 목표와 범위

다른 앱의 입력창을 선택하고 삼성 키보드를 사용하던 중에도, 어시스턴트
버튼으로 Relay를 호출해 말한 내용을 원래 커서 위치에 넣는다. 사용자는
키보드를 교체하거나 입력기를 전환하지 않는다.

- 기존 어시스턴트 호출, 녹음·전사 엔진과 로컬 저장을 재사용한다.
- 자동 입력은 Android 13/API 33 이상과 사용자가 활성화한 접근성 서비스를
  기준으로 구현한다. Android 12/12L에서는 기존 녹음·복사 흐름을 유지한다.
- 일반 텍스트 입력창을 우선 지원한다. 비밀번호 입력창은 제외한다.
- 입력창이 없으면 기존 음성 메모로 동작한다. 앱 내부에서 시작한 녹음은
  외부 앱에 자동 입력하지 않는다.
- 로컬 저장을 완료한 최종 전사문만 입력 대상으로 삼는다. 부분 결과나
  오류로 임시 확정한 결과는 자동 입력하지 않는다.
- 입력창의 선택 영역은 인식 결과로 대체하고, 선택 영역이 없으면 커서에
  삽입한다. 기존 초안 전체를 덮어쓰거나 메시지를 자동 전송하지 않는다.
- 완료 창에서 전사문 편집, 자동 후보정 모델, 파인튜닝은 후속 작업으로 둔다.
  이미 main에 있는 원본 녹음 보관·평가 ZIP 기능은 그대로 활용한다.

## 1. 최신 main에서 작업 준비

- 구현 시작 시 원격 main을 다시 확인하고 최신 main에서 작업 브랜치를 만든다.
  현재 로컬 main은 위 기준보다 두 커밋 뒤에 있으므로 오래된 코드에서 시작하지 않는다.
- 최신 `AGENTS.md`와 검증 스킬을 따른다. 기존 평가 데이터 보관·내보내기를
  새로 구현하거나 삭제하지 않는다.
- `com.hush.voice`, `hush.db`, 어시스턴트 컴포넌트 이름과 릴리스 서명을 유지한다.
  이 기능의 입력 대상·작업 상태는 메모리에 두며 DB 스키마 변경은 우선 피한다.

## 2. 가장 먼저 두 가지 동작 검증

### 어시스턴트 버튼 전달

삼성 기기에서 수동으로 다음 구성을 확인한다. 기존 기록·설정을 초기화하는
계측 테스트는 사용하지 않는다.

1. 기본 디지털 어시스턴트가 Relay인지 확인한다.
2. 측면 버튼 길게 누르기가 디지털 어시스턴트로 연결되는지 확인한다.
3. 삼성 키보드의 측면 버튼 음성 입력 단축키가 있으면 해제한다.
4. 키보드를 닫은 상태와 연 상태에서 각각 버튼으로 Relay를 호출한다.

3번 설정을 끄면 Relay로 전달된다는 것은 아직 검증되지 않은 가설이다.
해당 One UI에서 전달되지 않으면 원인을 먼저 확인하며, 실제 버튼 경로가
해결되기 전에는 이 요구사항을 완료로 표시하지 않는다. 다른 호출 제스처는
원인 분리용으로만 사용하고 요청한 버튼 동작을 대신했다고 보고하지 않는다.
설정의 정확한 명칭과 경로는 검증한 버전에 맞춰 앱 안내에 반영한다.

### 키보드를 유지한 텍스트 삽입

폐기 가능한 에뮬레이터의 테스트 입력창에서 접근성 입력 연결을 사용해
커서 삽입, 선택 영역 대체, 기존 키보드 유지 가능성을 먼저 검증한다.
Relay의 실제 어시스턴트 창을 열고 닫은 뒤에도 원래 입력창을 식별하고
연결을 다시 얻을 수 있어야 한다. 이 단계가 통과한 뒤 전체 녹음 흐름을 붙인다.

## 3. 접근성 입력 서비스와 대상 관리

예상 추가 파일: `RelayAccessibilityService.java`,
`AssistantInputTarget.java`, `res/xml/accessibility_service.xml`.
`AndroidManifest.xml`에 시스템 바인딩 권한으로 보호한 서비스를 등록한다.

- API 33 이상에서 `FLAG_INPUT_METHOD_EDITOR`와 접근성 입력 연결을 사용한다.
  사용자가 시스템 접근성 설정에서 직접 서비스를 활성화한다.
- 어시스턴트 호출 직전의 유효한 편집 필드 후보를 확보하고 작업 시작 시
  특정 대상과 묶는다. 창·앱·편집 필드 식별 정보와 연결 세대, 선택 영역 등
  재검증에 필요한 최소 정보만 일시 보관한다.
- 어시스턴트 창으로 인한 일시적 포커스 이동과 사용자의 다른 앱·필드 선택을
  구별한다. 원래 필드를 확실히 재식별할 수 없으면 자동 입력하지 않는다.
- 녹음·전사 중 원래 초안이나 커서가 변경되면 보수적으로 자동 입력을 중단한다.
  한글 조합 종료에 따른 정상 이벤트는 프로토타입 결과에 맞춰 구별한다.
- 비밀번호·지원하지 않는 입력 유형·연결 없음·권한 해제를 명시적으로 처리한다.
  화면 캡처나 전체 화면 내용 수집은 추가하지 않는다.
- 입력 대상은 작업 종료·취소·서비스 종료 시 폐기한다. 프로세스 재시작 후
  이전 전사문을 새 입력창에 자동 삽입하지 않는다.

## 4. 녹음 결과와 입력 수명 연결

예상 추가 파일: `AssistantDictationSession.java`.
연결 지점: `HushSession`, `RecordingPanel`, `DictationEngine.Listener`,
`CloudDictationEngine`의 완료 전달 경로.

- 어시스턴트에서 시작한 작업만 고유 작업 ID와 입력 대상을 가진다.
  녹음 결과 처리 책임을 `RecordingPanel`의 화면 수명과 분리한다.
- 상태 흐름은 `대상 확인 → 녹음 → 전사·로컬 저장 → 원래 필드 복귀 대기
  → 입력 1회 요청 → 종료`로 둔다. 실패·취소는 로컬 기록 또는 기존 복사로 연결한다.
- 전사 완료 후 어시스턴트 창을 닫아 원래 앱으로 돌아가고, 원래 대상의
  연결이 복귀했음을 확인한 뒤 `commitText`를 호출한다. 무제한 대기하지 않는다.
- 자동 입력을 위한 내부 창 닫기와 사용자가 누른 닫기·뒤로가기를 구분한다.
  사용자가 닫은 작업은 나중에 전사가 완료돼도 자동 입력하지 않는다.
- 현재 `HushSession.onHide()`는 패널을 닫고, `CloudDictationEngine.close()`는
  listener를 제거한다. 이 수명 연결을 그대로 둔 채 창을 닫고 입력을 기다리지 않는다.
- 중복 콜백·재호출·뒤늦은 결과로 같은 내용을 두 번 입력하지 않는다.
  접근성 `commitText`에는 입력 성공을 확정하는 반환값이 없으므로, 요청을
  보냈지만 결과가 불명확할 때 자동 재전송하지 않는다. 실제 입력 여부를
  확인할 수 없는 경우에도 성공을 확정한 문구를 표시하지 않는다.
- 전사 실패 시 기존 Pending recordings 복구와 명시적 재시도를 유지한다.
  과거 녹음의 수동 재시도는 이전 입력 대상에 자동 입력하지 않는다.
- 자동 입력 실패가 이미 저장된 전사문·녹음 보관을 취소하거나 데이터를
  삭제하지 않도록 한다. 기존 자동 복사 설정도 존중한다.

## 5. 설정과 상태 안내

연결 지점: `MainActivity`, `Prefs`, `README.md`.

- 설정에 어시스턴트 음성 입력의 지원 여부와 접근성 연결 상태를 표시한다.
  사용자가 이 기능을 선택하면 시스템 접근성 설정으로 안내한다.
- 기본 어시스턴트 선택과 삼성의 버튼 음성 입력 단축키 해제 경로를 안내한다.
  실제 확인되지 않은 설정을 앱에서 자동 변경하지 않는다.
- 권한 미설정·미지원 입력창에서는 저장·복사로 이어지고, 필요한 조치를
  짧게 알려준다. 녹음 파형은 실제 캡처 중에만 표시한다.
- 접근성 서비스가 활성화되어도 삽입은 명시적으로 시작한 어시스턴트 작업에
  한정한다. 녹음이나 입력창 내용·자격 증명을 로그에 남기지 않는다.

## 6. 검증과 완료 기준

자동화는 `com.hush.voice.HushTestRunner`와 검증 스킬의 폐기 가능한
에뮬레이터에서만 수행한다. 일반 키보드와 접근성 서비스가 함께 실행되는
실제 입력 연결을 검증하며, 가짜 완료 콜백 테스트만으로 끝내지 않는다.

- 초안 중간 커서에 삽입하고 선택 영역만 대체한다. 한글 조합 중 호출도 확인한다.
- 어시스턴트 창 복귀 후 원래 필드에만 입력된다. 사용자가 앱·필드·커서를
  변경하면 입력되지 않는다. 입력창 없음·비밀번호·커스텀 입력창도 확인한다.
- 닫기·뒤로가기·권한 해제·프로세스 종료·중복 호출·늦은 전사 완료 시
  오입력과 중복 입력이 없고, 사용자가 작성하던 초안이 보존된다.
- Groq/Custom과 시스템 음성 엔진의 완료 경로를 확인한다. 임시 전사와
  Pending recordings 재시도는 자동 입력하지 않는다.
- 기존 transcript 저장·편집·복구, 보관 옵션 켬/끔, 최초 전사 보존,
  평가 ZIP 내보내기와 credential/HTTPS 처리가 유지된다.
- `./gradlew assembleDebug assembleDebugAndroidTest lintDebug`를 통과한다.
  릴리스 전달 단계에서는 로컬 서명으로 `assembleRelease lintRelease`를 실행한다.
- 삼성 실기기에서는 초기화 없는 수동 검증으로, 키보드가 열린 상태의
  실제 측면 버튼 호출부터 일반 메시지 입력창에 결과 삽입까지 확인한다.
  메시지 전송은 하지 않는다. 해당 검증 전에는 실기기 완료를 주장하지 않는다.

완료 증거는 지원 OS·One UI, 버튼 설정, 테스트한 입력창 종류와 결과,
실패 시 복사 경로를 기록한다. 개인 기기 식별자·실제 녹음·비밀정보는
저장소와 PR 증거에 포함하지 않는다.

## 작업 분할

1. 버튼 전달과 API 33 접근성 입력의 작은 프로토타입 및 결과 기록.
2. 대상 관리·접근성 서비스·오입력 방지 검증.
3. 어시스턴트 녹음 결과 연결, 창 복귀 및 취소 처리.
4. 설정 안내·기존 기능 회귀 검증·삼성 수동 검증·문서화.

각 단계가 동작하는 상태로 나누어 검토하고, PR은 저장소 규칙대로 squash merge한다.

## 2026-11-22 구현 기록

- 최신 main에서 별도 작업 브랜치로 구현했다.
- 입력 대상 관리는 `RelayAccessibilityService.Request`에 모았다. 별도
  코디네이터로 엔진을 재작성하지 않고, `RecordingPanel`이 로컬 저장 후
  완료를 전달하고 `HushSession`이 창을 닫은 다음 한 번만 입력을 요청한다.
  전사 중 사용자가 창을 닫으면 기존 listener 해제로 자동 입력을 막는다.
- 접근성 서비스, 사용자 선택 설정, 키보드 높이를 고려한 어시스턴트 배치,
  취소·포커스·초안·선택 영역·권한·잠금 검사를 추가했다.
- 기존 DB, 녹음 보관 및 평가 ZIP 경로는 변경하지 않았다.
- Android 에뮬레이터의 실제 어시스턴트 키·키보드·접근성 연결로 동작을
  검증한다. 삼성 실기기가 연결되지 않아 One UI의 측면 버튼 경로는 미검증이다.
- 결과와 한계는 [검증 기록](../verification/assistant-input.md)에 유지한다.
